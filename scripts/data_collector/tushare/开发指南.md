## 架构概述

### 整体架构

Tushare Data Collector 采用**分层抽象 + 具体实现**的架构设计，遵循面向对象的设计原则，具有良好的可扩展性和可维护性。


### 设计原则

1. **单一职责原则**：每个类只负责一个明确的功能
2. **开闭原则**：对扩展开放，对修改关闭
3. **依赖倒置原则**：依赖抽象而非具体实现
4. **接口隔离原则**：使用抽象基类定义清晰的接口

#### 2.2 数据获取模块

**日线数据获取** (`_get_daily_data`)：

```python
def _get_daily_data(self, ts_code, start_date, end_date):
    # 1. 调用 Tushare API
    df = self.pro.daily(ts_code=ts_code, start_date=start_date, end_date=end_date)
    
    # 2. 获取复权因子
    adj_factor_df = self.pro.adj_factor(ts_code=ts_code, ...)
    
    # 3. 计算复权价格
    #    - 原始价格：open, high, low, close（未复权）
    #    - 后复权价格：close_hfq = close * factor
    #    - 前复权价格：close_qfq = close * (factor / factor_latest)
    
    # 4. 合并数据
    df = df.merge(adj_factor_df, on='date', how='left')
    
    # 5. 返回标准化格式
    return df[['symbol', 'date', 'open', 'high', 'low', 'close', 'volume', 
               'factor', 'open_qfq', 'high_qfq', 'low_qfq', 'close_qfq',
               'open_hfq', 'high_hfq', 'low_hfq', 'close_hfq']]
```

**复权价格计算逻辑**：

```python
# 后复权（后复权 = 原始价格 × 累积复权因子）
df['close_hfq'] = df['close'] * df['factor']

# 前复权（前复权 = 原始价格 × (factor / factor_latest)）
# factor_latest 是最近一个交易日的 factor
factor_latest = df_sorted['factor'].iloc[-1]
factor_qfq = df['factor'] / factor_latest
df['close_qfq'] = df['close'] * factor_qfq
```

**设计要点**：
- **存储策略**：同时存储原始价格、前复权价格、后复权价格，提供最大灵活性
- **错误处理**：如果获取复权因子失败，使用默认值1.0
- **API延迟**：每次API调用后添加延迟，避免触发频率限制

**分钟线数据获取** (`_get_minute_data`)：

```python
def _get_minute_data(self, ts_code, start_date, end_date, freq):
```

**缓存使用场景**：

1. **增量更新**：检查缓存的最新日期，只下载新数据
2. **断点续传**：如果收集中断，可以从缓存恢复
3. **避免重复请求**：相同股票相同时间范围的数据直接从缓存读取

#### 2.4 增量更新机制

**核心方法**：`_collect_single_stock`

```python
def _collect_single_stock(self, ts_code):
    # 1. 检查CSV文件是否已存在且完整
    if csv_file.exists():
        existing_df = pd.read_csv(csv_file)
        if (existing_start <= start_datetime and 
            existing_end >= end_datetime):
            # 检查是否有额外字段需求
            if extra_fields:
                missing_fields = [f for f in extra_fields 
                                 if f not in existing_df.columns]
                if not missing_fields:
                    return None  # 跳过，数据已完整
            else:
                return None  # 跳过，数据已完整
    
    # 2. 检查缓存
    cached_df = self._get_cached_data(ts_code)
    if cached_df is not None:
        cached_end = cached_df['date'].max()
        if cached_end >= end_datetime:
            return cached_df  # 使用缓存
        else:
            # 增量更新：只下载新数据
            start_date = (cached_end + pd.Timedelta(days=1)).strftime('%Y%m%d')
            cached_df_for_merge = cached_df.copy()
    
    # 3. 获取新数据
    df = self._get_daily_data(ts_code, start_date, end_date)
    
    # 4. 合并缓存数据（如果有）
    if cached_df_for_merge is not None:
        df = pd.concat([cached_df_for_merge, df], ignore_index=True)
        df = df.drop_duplicates(subset=['date'], keep='last')
    
    # 5. 保存缓存
    self._save_cached_data(ts_code, df)
    
    return df
```

**设计要点**：
- **智能跳过**：如果数据已存在且完整，直接跳过，不重复下载
- **增量合并**：只下载缺失的数据，与现有数据合并
- **去重处理**：使用 `drop_duplicates` 确保数据唯一性

**额外字段获取** (`_get_extra_data`)：

```python
def _get_extra_data(self, ts_code, start_date, end_date):
    # 1. 分类字段
    financial_fields = [f for f in extra_fields if f in INDICATOR_TYPES['financial']]
    basic_fields = [f for f in extra_fields if f in INDICATOR_TYPES['basic']]
    moneyflow_fields = [f for f in extra_fields if f in INDICATOR_TYPES['moneyflow']]
    
    # 2. 分别获取不同类型的数据
    if financial_fields or basic_fields:
        df_financial = self._get_financial_indicators(...)
    
    if moneyflow_fields:
        df_moneyflow = self._get_moneyflow_data(...)
    
    # 3. 合并所有数据
    result = df_financial.merge(df_moneyflow, on='date', how='outer')

```

**设计要点**：
- **增量添加**：不需要重新下载基础数据（OHLCV），只下载新字段
- **字段分类**：根据字段类型调用不同的API接口
- **数据合并**：使用 `merge` 按日期合并，保留现有数据

#### 2.6 并发控制

**并发策略**：

```python
def collect(self):
    with ThreadPoolExecutor(max_workers=self.max_workers) as executor:
        futures = {executor.submit(self._collect_single_stock, ts_code): ts_code 
                  for ts_code in self.stock_list}
        
        for future in as_completed(futures):
            ts_code = futures[future]
            try:
                df = future.result()
                if df is not None and not df.empty:
                    # 保存数据
                    csv_file = save_dir / f"{normalized_code}.csv"
                    df.to_csv(csv_file, index=False)
            except Exception as e:
                logger.error(f"✗ {ts_code}: {e}")
```

**设计要点**：
- **线程池**：使用 `ThreadPoolExecutor` 实现并发
- **异步处理**：使用 `as_completed` 处理完成的任务
- **错误隔离**：单个股票失败不影响其他股票

#### 2.7 重试机制

**装饰器实现**：

```python
def deco_retry(retry: int = 5, retry_sleep: int = 3):
    def deco_func(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _i in range(1, retry + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if _i == retry:
                        raise
                    time.sleep(retry_sleep)
        return wrapper
    return deco_func

# 使用
@deco_retry(retry=5, retry_sleep=3)
def _get_daily_data(self, ts_code, start_date, end_date):
    ...
```

**设计要点**：
- **自动重试**：API调用失败时自动重试
- **指数退避**：重试间隔逐渐增加（可选）
- **最终失败**：达到最大重试次数后抛出异常

```python
def get_index_constituents(self, index_code, output_file=None):
    # 方法1: 尝试使用 index_weight 接口（需要日期）
    for i in range(0, 30):  # 尝试最近30个交易日
        check_date = (datetime.now() - timedelta(days=i)).strftime('%Y%m%d')
        df = self.pro.index_weight(index_code=index_code, trade_date=check_date)
        if df is not None and not df.empty:
            break
    
    # 方法2: 如果 index_weight 失败，尝试使用 index_cons 接口
    if df is None or df.empty:
        df = self.pro.index_cons(index_code=index_code)
    
    # 提取股票代码
    if 'con_code' in df.columns:
        stock_list = df['con_code'].unique().tolist()
    elif 'ts_code' in df.columns:
        stock_list = df['ts_code'].unique().tolist()
    
    return stock_list
```

**设计要点**：
- **多接口尝试**：如果第一个接口失败，尝试备用接口

- **代码映射**：支持简写代码（如 'hs300'）到完整代码（'000300.SH'）的映射

```
  │   │   │   │   ├─→ 字段完整？ → 返回 None（跳过）

```

```
   └─→ 缺失日期：2025-01-01 到 2025-01-31
```

```
   └─→ existing_df = pd.read_csv(csv_file)

2. 获取新字段数据
   └─→ extra_df = _get_financial_indicators(ts_code, ...)
       └─→ 只包含 date, pe, pb, ps 列

3. 合并数据
   └─→ result_df = existing_df.merge(extra_df, on='date', how='left')
       └─→ 保留所有现有字段，添加新字段

4. 保存
   └─→ result_df.to_csv(csv_file, index=False)
```

## 关键实现细节

### 1. 股票代码标准化

**Tushare格式 → Qlib格式**：

```python
def normalize_symbol(self, symbol: str) -> str:
    # Tushare格式：000001.SZ, 600000.SH
    # Qlib格式：SZ000001, SH600000
    
    if '.' in symbol:
        code, market = symbol.split('.')
        if market == 'SZ':
            return f"SZ{code}"
        elif market == 'SH':
            return f"SH{code}"
    return symbol
```

**设计要点**：
- **格式转换**：Tushare使用 `代码.市场` 格式，Qlib使用 `市场代码` 格式
- **文件命名**：使用 `code_to_fname()` 处理特殊字符（如 `/` 转换为 `_`）

### 2. 复权价格计算

**复权因子来源**：
- Tushare的 `adj_factor` 是**累积复权因子**
- 最新日期的 `adj_factor` 通常为 1.0（或接近1.0）

**计算逻辑**：

```python
# 获取复权因子
adj_factor_df = self.pro.adj_factor(ts_code=ts_code, ...)
df = df.merge(adj_factor_df[['date', 'factor']], on='date', how='left')

# 后复权价格（保持历史价格不变，调整最新价格）
df['close_hfq'] = df['close'] * df['factor']

# 前复权价格（保持最新价格不变，调整历史价格）
factor_latest = df_sorted['factor'].iloc[-1]  # 最新日期的factor
factor_qfq = df['factor'] / factor_latest
df['close_qfq'] = df['close'] * factor_qfq
```

**存储策略**：
- **原始价格**：`open, high, low, close`（未复权）
- **复权因子**：`factor`（累积复权因子）
- **前复权价格**：`open_qfq, high_qfq, low_qfq, close_qfq`
- **后复权价格**：`open_hfq, high_hfq, low_hfq, close_hfq`

**优势**：
- 用户可以根据需求选择使用哪种价格
- 保留原始数据，便于后续处理

### 3. API频率限制处理

**策略**：
1. **请求延迟**：每次API调用后添加 `delay` 秒延迟
2. **并发控制**：限制 `max_workers` 数量
3. **重试机制**：API失败时自动重试

**实现**：

```python
# 在每次API调用后添加延迟
df = self.pro.daily(ts_code=ts_code, ...)
if self.delay > 0:
    time.sleep(self.delay)
```

**建议配置**：
- 免费用户：`delay=0.5`, `max_workers=2`
- 付费用户：`delay=0.1`, `max_workers=4`

### 4. 错误处理策略

**分层错误处理**：

1. **API层**：使用 `@deco_retry` 装饰器自动重试
2. **数据层**：检查数据是否为空，处理缺失值
3. **文件层**：捕获文件读写异常，记录日志

**错误记录**：

```python
try:
    df = self._get_daily_data(ts_code, ...)
except Exception as e:
    logger.warning(f"获取日线数据失败 {ts_code}: {e}")
    return None
```

**设计要点**：
- **优雅降级**：单个股票失败不影响整体流程
- **详细日志**：记录错误信息，便于排查
- **数据验证**：检查数据完整性，避免保存错误数据

### 5. 数据完整性检查

**检查项**：

1. **日期范围**：检查数据是否覆盖指定时间范围
2. **数据长度**：检查数据量是否满足 `check_data_length` 要求
3. **字段完整性**：检查必需字段是否存在
4. **数据质量**：检查是否有异常值（如价格为0、成交量为负等）

**实现**：

```python
# 检查日期范围
if (existing_start <= start_datetime and 
    existing_end >= end_datetime):
    # 数据完整
    return None

# 检查数据长度
if len(df) < self.check_data_length:
    logger.warning(f"数据量不足: {symbol}")
    # 缓存到 mini_symbol_map，后续重试
    return self.CACHE_FLAG
```

### 6. 缓存机制设计

**缓存文件结构**：

```
save_dir/
├── .cache/
│   ├── 000001.SZ_1d.csv
│   ├── 600000.SH_1d.csv
│   └── ...
├── SZ000001.csv
├── SH600000.csv
└── ...
```

**缓存使用场景**：

1. **增量更新**：检查缓存最新日期，只下载新数据
2. **断点续传**：收集中断后，从缓存恢复
3. **避免重复请求**：相同请求直接从缓存读取

**缓存更新策略**：

```python
# 读取缓存
cached_df = self._get_cached_data(ts_code)

# 检查是否需要更新
if cached_df is not None:
    cached_end = cached_df['date'].max()
    if cached_end < end_datetime:
        # 增量更新：只下载新数据
        start_date = (cached_end + pd.Timedelta(days=1)).strftime('%Y%m%d')
        new_df = self._get_daily_data(ts_code, start_date, end_date)
        # 合并
        df = pd.concat([cached_df, new_df], ignore_index=True)
        df = df.drop_duplicates(subset=['date'], keep='last')
```

```python
def _validate_data(self, df: pd.DataFrame, ts_code: str) -> bool:

    required_fields = ['symbol', 'date', 'open', 'high', 'low', 'close', 'volume']
```

## 常见问题与解决方案

### 1. API调用频率限制

**问题**：触发Tushare API频率限制，返回错误

**解决方案**：
- 增加 `delay` 参数（建议：0.5秒）
- 减少 `max_workers`（建议：2）
- 使用付费账户提高限制

### 2. 数据不完整

**问题**：某些股票数据量不足

**解决方案**：
- 使用 `check_data_length` 参数检查数据长度
- 使用 `max_collector_count` 参数重试
- 检查股票是否已退市或停牌

### 3. 内存占用过高

**问题**：收集大量股票时内存占用过高

**解决方案**：
- 分批处理：使用 `limit_nums` 参数限制数量
- 及时释放：处理完一只股票后立即保存，不保留在内存
- 使用生成器：对于大量股票，使用生成器逐个处理

### 4. 缓存文件损坏

**问题**：缓存文件读取失败

**解决方案**：
- 自动处理：代码中已包含异常处理，会重新下载
- 手动清理：删除 `.cache` 目录强制重新下载
- 验证缓存：添加缓存文件完整性检查

### 5. 日期格式不一致

**问题**：不同API返回的日期格式不一致

**解决方案**：
- 统一转换：使用 `pd.to_datetime()` 统一转换
- 格式指定：明确指定日期格式 `format='%Y%m%d'`

### 6. 复权价格计算错误

**问题**：复权价格计算不正确

**解决方案**：
- 检查复权因子：确认 `adj_factor` 数据是否正确
- 验证计算：对比Tushare官方复权价格
- 使用原始价格：如果复权计算有问题，使用原始价格

## 总结

Tushare Data Collector 采用**分层抽象 + 具体实现**的架构设计，具有以下特点：

1. **可扩展性**：通过抽象基类定义接口，易于扩展新功能
2. **可维护性**：代码结构清晰，职责分明
3. **健壮性**：完善的错误处理和重试机制
4. **高效性**：支持并发收集、增量更新、本地缓存
5. **灵活性**：支持多种数据源、时间粒度、字段扩展

**核心设计模式**：
- **模板方法模式**：BaseCollector 定义流程，子类实现具体逻辑
- **策略模式**：不同的数据获取策略（日线、分钟线、额外字段）
- **装饰器模式**：重试装饰器、延迟控制

**最佳实践**：
- 使用缓存避免重复请求
- 增量更新减少API调用
- 字段扩展不重新下载基础数据
- 完善的日志记录便于排查问题
